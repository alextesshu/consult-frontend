# UI v2 — план переходу сторінка за сторінкою

Додати як новий розділ у `docs/UI_MIGRATION_PLAN.md`.

## Принцип
- Одна сторінка = один PR. Кожна сторінка під v2 отримує нову розмітку на класах `.pc2-*`, перемикання через `isUiV2()` або CSS-селектор `html[data-ui="v2"] .x`.
- Логіка, store, API, роути не змінюються. Якщо сторінці потрібна нова поведінка (напр., реєстрація з 3 полів), вона йде **окремим PR** після візуального.
- v1 лишається робочим до етапу 5. Кожен PR перевіряється в обох режимах (`?ui=v1`, `?ui=v2`).

## Етап 0 — інфраструктура (1 PR)
Файли з `PATCHES.md`: токени, компоненти, прапорець, Onest. Перевірка: на `?ui=v2` фон стає пласким кремовим #FBF9F5, шрифт Onest 400, фокус — темно-синя рамка. На `?ui=v1` нічого не змінилося.

Решта сторінок (без нових макетів):
Застосувати токени й компоненти без зміни структури: calendar → billing → settings → блог → чати → відгуки → аналітика. Для кожної: замінити кнопки/поля/картки/теги на `.pc2-*`, радіуси за шкалою, прибрати font-weight 700 з заголовків. Макети для них — окремий раунд дизайну, якщо потрібно.

## Етап 5 — увімкнення за замовчуванням
1. Staging `VITE_UI_V2=true` ≥ 1 тиждень, smoke за `STAGING_FE_SMOKE_TEST_TEMPLATE.md`.
2. Production `VITE_UI_V2=true`; `?ui=v1` ще працює як аварійний відкат.
3. Через 2 релізи без регресій: видалити v1-гілки розмітки, Inter з `style.css`, legacy-токени (`--sky-*`, `--color-primary-*` тощо), примітку v1 в `UI_SHAPE_STANDARD.md`.

## Чекліст для кожного PR
- [ ] `?ui=v1` виглядає як до PR
- [ ] `?ui=v2` відповідає макету (кольори/радіуси — лише токени)
- [ ] 375 / 768 / 1280 / 1440px без горизонтального скролу
- [ ] Клавіатура: Tab доходить до всіх дій, видно фокус
- [ ] Стани loading / empty / error / disabled на місці
- [ ] Тексти не змінені (окрім узгоджених у макеті)
- [ ] `npm run test` зелений
