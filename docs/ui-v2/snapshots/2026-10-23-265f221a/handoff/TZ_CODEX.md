# ТЗ для Codex: ProConsult UI v2

**Мета:** перевести frontend на новий візуальний шар UI v2 так, щоб функціональність не змінилася. Новий вигляд вмикається прапорцем `data-ui="v2"`. Без прапорця все виглядає й працює як зараз.

**Репозиторій:** `frontend` (Vue 3 + TS + Vite + Pinia + Vitest), гілка `dev`. Діють правила `AGENTS.md`: спершу план і список файлів, не комітити без прямого запиту, PowerShell.

## 2. Зафіксовані рішення (не обговорюються)

- Шрифт **Onest** 400/500/600. Заголовки 500, ніколи 700. Вага 600 — тільки для чисел. Основний текст 400.
- Фон сторінки пласкі кремовий `--pc-bg-main` #FBF9F5, без radial-градієнтів.
- Головна дія — темно-синя `--pc-navy-900`. М'ятний і персиковий — лише підкладки з текстом відповідного `*-ink`.
- Радіуси: 8 — теги; 12 — поля й квадратні кнопки; **16 — картки й панелі**; 24 — hero, діалоги, нижній лист; pill — CTA, чипи, сегменти.
- Картка за замовчуванням без тіні: біла, рамка `--pc-border-hair`.
- Фокус: `:focus-visible` — 2px navy outline, offset 2px. Disabled — opacity .45.
- Пароль: **одне поле + кнопка «Показати / Сховати»**, без «Повторіть пароль».
- Реєстрація (спеціаліст і клієнт): ім'я, email, пароль + одне питання чипами. Решта — в онбординг.
- Рух: 150 / 200 / 400 мс, `cubic-bezier(.4,0,.2,1)`; повага до `prefers-reduced-motion`.

Кожне завдання — окремий PR. Наступне починаємо лише після приймання попереднього.

5. `docs/UI_SHAPE_STANDARD.md`: на початку примітка «Діє лише для v1. Для v2 — DESIGN_SYSTEM.md §8».

**Приймання:** `?ui=v1` — без змін; `?ui=v2` — тло #FBF9F5, шрифт Onest 400, navy фокус-рамка; тести зелені.

### 4.2 Сесії + деталі сесії — є макет `Sessions.dc.html` (PR: 4.2a вигляди, 4.2b панель деталей, 4.2c drag-перенос)
- **Три вигляди з перемикачем:** Тиждень (за замовчуванням, Пн–Нд, 8:00–21:00) · Список за днями · Дошка (Чекає підтвердження → Підтверджено → Потребує завершення → Завершено → Скасовано/неявка). Останній обраний вигляд можна запам’ятати в `localStorage`.
- **Колір = статус.** «Потребує завершення» — минула сесія зі статусом CONFIRMED або COMPLETED без нотатки / з неоплаченою оплатою (обчислюється на фронтенді з наявних полів).
- **Сесії без реєстрації** — у тому ж календарі, пунктирна рамка + позначка «без реєстрації» (дані з `ExternalSessionsView`/його API).
- **Запит клієнта на перенос** — позначка ⇄ на сесії в усіх виглядах; у панелі деталей «Погодити перенос» / «Відхилити» (існуючі виклики з блоку «Запити на перенос»).
- **Перенос перетягуванням (тиждень):** тягнути можна лише майбутні SCHEDULED/CONFIRMED; під час перетягування підсвічуються **вільні вікна** (бекенд переносить тільки у вільний слот — `test_sessions_reschedule.py`: відхиляє зайнятий, минулий, чужий слот і перенос після початку). Відпустили на вікні → `reschedule_session`, тост «Перенесено · клієнт отримає повідомлення» + «Скасувати» (повторний reschedule назад у старий слот). Відпустили не на вікні → блок повертається. Альтернатива без миші — чипи вільних вікон у панелі деталей.
- **Клік по порожньому часу** → drawer «Нова сесія» з цим часом; клік по вільному вікну → те саме з вікном.
- **Панель деталей справа з вкладками** (не окрема сторінка; роут `/cabinet/sessions/:id` відкриває список із панеллю). Обрано варіант «вкладки»:
  - Шапка: статус, «без реєстрації», клієнт, дата/час/формат; банер ⇄ запиту на перенос (Погодити / Відхилити).
  - Вкладки **Сесія · Нотатки · Оплата · Клієнт**; помаранчева крапка на вкладці, де бракує даних після сесії (немає нотатки / не оплачено).
  - **Сесія:** до сесії — підтвердження (SCHEDULED), формат і посилання, перенос (чипи вільних вікон), скасування; після — «Відбулась / Неявка» і «Наступна сесія» (чипи вільних вікон + «Повторювати щотижня» — серію створювати тут; окрема дія «Повторювати щотижня» зникає).
  - **Нотатки:** приватна нотатка (автозбереження) + матеріал / домашнє завдання.
  - **Оплата:** ціна + «Оплачено / Ще не оплачено»; підказка «клієнт платить напряму».
  - **Клієнт:** кількість сесій, з якого часу, неоплачені, теми, остання нотатка, посилання на картку клієнта.
  - Футер після сесії: підсумок (нотатка ✓ · оплачено ✓ · наступна ✓) + одна кнопка «Завершити сесію» / «Позначити неявку» — замість completion-модалки.
- **Регулярні сесії (серія) — разовий перенос:** позначка ↻ на сесії. Перетягування або чипи в панелі переносять **лише цю дату** (тост «Перенесено лише цю сесію»), наступні сесії серії лишаються в регулярний час; у панелі — пояснення і «Разово перенесено з Чт 16:30». Зміна самого регулярного часу — лише в картці клієнта (Контакти → «Оновити майбутні сесії? Оновити всі / Лише нові»). Використовувати існуючий `reschedule_session` для однієї сесії; серію не чіпати.
- **Скасування спеціалістом** — один клік + тост «Скасувати» 5 с (виклик відкладений до закриття тосту). Причина не обов’язкова.
- **Hero сторінки:** назва тижня + ← → і «Цей тиждень» (якщо не поточний); перемикач Тиждень/Список/Дошка; «+ Нова сесія» (drawer `create`). Лічильники-кнопки: «Сесій за тиждень» → Тиждень, «Чекають підтвердження» і «Потребують завершення» → Дошка, «Запити на перенос» → Список.
- **Тиждень:** лінія «зараз» лише на поточному тижні; сьогоднішня колонка підсвічена; легенда статусів під сіткою. Вільні вікна — пунктир «вільно · 19:30». Клік по порожньому часу: ctx «буде створено вікно й сесію» (крок 30 хв).
- **Позначки на блоці:** ↻ серія · ⇄ запит на перенос · ● потребує завершення · ! підтверджена майбутня онлайн-сесія без посилання. У списку/дошці/панелі ті самі стани — текстовими прапорцями: «без реєстрації», «⇄ просить перенос», «нова клієнтка», «без нотатки», «оплата?», «без посилання».
- **Відмови при перетягуванні** (тост без «Скасувати»): «Минулі сесії не переносяться» · «Цю сесію не можна перенести» (скасована/неявка/завершена) · «Перенести можна лише на вільне вікно — його позначено пунктиром». Клік без руху (<5 px) = відкрити панель.
- **Дошка:** швидкі кнопки на картці — «Підтвердити» (Чекає підтвердження) і «Завершити» (відкриває панель).
- **Панель «Сесія» до початку:** блок рішення (SCHEDULED: «Підтвердити» / «Скасувати»; для нової клієнтки — текст про лист із деталями); CONFIRMED: «Скасувати сесію». Немає посилання → «Додати посилання» (drawer `link`). Остання нотатка клієнта — через `PrivateReveal`.
- **Нотатки:** чипи матеріалів «+ Щоденник думок…» (з бібліотеки спеціаліста); індикатор «Збережено» після автозбереження.
- **Футер:** до сесії — «Зберегти» + «Зміни бачите лише ви»; після — підсумок «нотатка ✓ · оплачено ✓ · наступна ✓» і «Завершити сесію» / «Позначити неявку» (за вибором «Відбулась / Неявка»). При неявці оплату не чіпати. «Повторювати в цей час» — сегмент Ні / Щотижня / Раз на 2 тижні (= `ClientRegularTime.frequency`: `weekly` | `every_two_weeks`), активний лише після вибору наступного вікна.
- **Тости з undo:** підтвердження, скасування, перенос, погодження/відхилення переносу, завершення, створення сесії. Undo = відкладений виклик API або зворотна дія; одночасно лише один тост.

Черга роботи: undo = існуючий reopen. **Рішення по запитах (approve/reject) і переходи admin inbox на бекенді незворотні** — тому запит відправляти лише після закриття тосту (відкладене виконання); при переході зі сторінки / закритті вкладки — відправити одразу. «Відхилити» — drawer з причиною (kind: reject, `admin_note`).

Після approve картка показує «Погоджено · не застосовано» і кнопку «Застосувати {plan}» → drawer зміни тарифу (існуючий виклик «Змінити базовий тариф»). - **Глобальна проблема** (напр. «Домен відправника не підтверджено», N недоставлених листів, з дати) — банер `.pc2-alert` над усіма розділами адмінки, поки елемент черги критичного типу відкритий; клік → цей елемент у Черзі.

- **Адмін-запити:** у hero «N непрочитаних запитів» / «Усе прочитано»; фільтр «Непрочитані»; непрочитаний — крапка перед заголовком.
- **Доступ і тарифи:** «Очікують рішення: N» / «Усі запити опрацьовано»; фільтри Очікують · Погоджено · Відхилено. Запит ліміту показує «Потрібно N активних клієнтів замість M» і коментар спеціаліста; «Немає пов’язаного елемента», якщо в черзі нічого не закрилось.

### 4.10 Адаптив кабінету й адмінки — макет `Cabinet-Mobile.dc.html` (PR після відповідного 4.x, по одному на сторінку)
