# ТЗ для Codex: ProConsult UI v2

> Imported reference specification. [Master TZ](PROCONSULT_UI_V2_CODEX_MASTER_TZ.md)
> takes precedence for stage separation, approval gates, product contracts, and rollout.
> Stage 0A imports only; the infrastructure section below is Stage 0B and is not authorized.
> Single-password/minimal-signup behavior requires separate stages 1.3b/2.3b.

**Мета:** перевести frontend на новий візуальний шар UI v2 так, щоб функціональність не змінилася. Новий вигляд вмикається прапорцем `data-ui="v2"`. Без прапорця все виглядає й працює як зараз.

**Репозиторій:** `frontend` (Vue 3 + TS + Vite + Pinia + Vitest), гілка `dev`. Діють правила `AGENTS.md`: спершу план і список файлів, не комітити без прямого запиту, PowerShell.

## 2. Зафіксовані рішення (не обговорюються)

- Шрифт **Onest** 400/500/600. Заголовки 500, ніколи 700. Вага 600 — тільки для чисел. Основний текст 400.
- Фон сторінки пласкі кремовий `--pc-bg-main` #FBF9F5, без radial-градієнтів.
- Головна дія — темно-синя `--pc-navy-900`. М'ятний і персиковий — лише підкладки з текстом відповідного `*-ink`.
- Радіуси: 8 — теги; 12 — поля й квадратні кнопки; **16 — картки й панелі**; 24 — hero, діалоги, нижній лист; pill — CTA, чипи, сегменти.
- Картка за замовчуванням без тіні: біла, рамка `--pc-border-hair`.
- Фокус: `:focus-visible` — 2px navy outline, offset 2px. Disabled — opacity .45.
- Пароль: **одне поле + кнопка «Показати / Сховати»**, без «Повторіть пароль».
- Реєстрація (спеціаліст і клієнт): ім'я, email, пароль + одне питання чипами. Решта — в онбординг.
- Рух: 150 / 200 / 400 мс, `cubic-bezier(.4,0,.2,1)`; повага до `prefers-reduced-motion`.

## 3. Заборонено

- Змінювати роути, API-виклики, store, permission-логіку, назви статусів з бекенду.
- Змінювати тексти з юридичним змістом, ціни, ліміти тарифів (брати з поточного коду, не з макета).
- Додавати рейтинги, «топ», «перевірений спеціаліст» тощо.
- Видаляти loading / empty / error / disabled стани.
- Ламати v1: кожна зміна має бути або в нових класах `.pc2-*`, або під `html[data-ui="v2"]`, або за `isUiV2()`.
- Хардкодити hex / px, які є в токенах.
- Ставити `font-weight: 700` на заголовки у v2.
- Змішувати візуальні зміни й зміни поведінки в одному PR.

## 4. Завдання по черзі

Кожне завдання — окремий PR. Наступне починаємо лише після приймання попереднього.

### Етап 0 — інфраструктура
1. `src/main.ts`: після `import './style.css'` додати `./styles/tokens-v2.css`, `./styles/components-v2.css`; викликати `applyUiVersion()` до `createApp`.
2. `index.html`: preconnect + Onest (`wght@400;500;600`, `subset=cyrillic,latin`).
3. `.env.example`: `VITE_UI_V2=`.
4. `src/lib/uiVersion.spec.ts`: query > localStorage > env; невалідні значення ігноруються.
5. `docs/UI_SHAPE_STANDARD.md`: на початку примітка «Діє лише для v1. Для v2 — DESIGN_SYSTEM.md §8».

**Приймання:** `?ui=v1` — без змін; `?ui=v2` — тло #FBF9F5, шрифт Onest 400, navy фокус-рамка; тести зелені.

### 1.1 Публічний хедер — `App.vue`
Під v2: `.pc2-header` (76px, лого 40px), вкладки «Для спеціалістів / Для клієнтів» як `.pc2-header__link`, CTA `.pc2-btn--primary`.
**Приймання:** усі посилання й умови показу за роллю як раніше; мобільне меню працює; немає горизонтального скролу на 375px.

### 1.2 Головна — `HomeView.vue`
Під v2 за `Home.dc.html`: hero → схема «сторінка → запит → сесія → робота» з живою карткою → блок практики → тарифи → фінальний CTA.
**Приймання:** CTA ведуть на ті самі роути; ціни й тексти тарифів — з поточного коду; анімації вимикаються при reduced-motion.

### 1.3a Реєстрація спеціаліста, візуал — `SignupView.vue`
`.pc2-input--lg`, `.pc2-password`, `.pc2-chips`, `.pc2-steps`, кнопка `.pc2-btn--primary.pc2-btn--lg.pc2-btn--block`. Поля й валідацію **не змінювати**.

### 1.3b Реєстрація спеціаліста, поведінка
Прибрати «Повторіть пароль» і його валідацію. Перед цим перевірити в `AI_CONTRACT.md`, що бекенд не вимагає `password_confirmation`; якщо вимагає — зупинитися й повідомити. Лишити ім'я / email / пароль / спеціалізацію (чипи). Оновити тести.

### 2.1 Профіль спеціаліста — `PublicProfileView.vue` + `public-profile/*`
Сітка `minmax(0,1fr) 380px`; `.pc2-request-panel` липка (top 96px), <860px — нижній лист. Усередині панелі покроково: оффер → вільний час → контакт.
**Приймання (критично):** вибір вікна створює **запит**, не підтверджену сесію; приховані оффери не показуються; «Парна консультація» — лише якщо налаштована; slug-роут і видимість не змінені.

### 2.2 Пошук — `PublicTherapistsView.vue`, `PublicSpecialistCard.vue`
Фільтри `.pc2-chips`, картки `.pc2-card.pc2-card--interactive`.
**Приймання:** без рейтингів і сортування «найкращі»; фільтри, пошук, пагінація як раніше.

### 2.3a / 2.3b Реєстрація клієнта — `ClientSignupView.vue`
Так само, як 1.3a / 1.3b. Запит без реєстрації має працювати як раніше.

### 3.1 Кабінет клієнта — `ClientDashboardView.vue`
Hero найближчої сесії (`.pc2-card--lg`, 24px), матеріали — `.pc2-card--interactive`, статуси — `.pc2-tag--*`.
**Приймання:** показуються лише опубліковані матеріали; підтвердження сесії й статус оплати — окремі бейджі.

### Етап 4 — кабінет спеціаліста (по одній сторінці)
Порядок: dashboard → sessions → session detail → clients → client detail → calendar → billing → settings → admin.
Структуру не змінювати: лише замінити кнопки / поля / картки / теги на `.pc2-*`, радіуси за шкалою, заголовки 500. Нових блоків не вигадувати.

### Етап 5 — не виконувати без окремої команди
Увімкнення v2 за замовчуванням і видалення v1.

## 5. Формат кожної відповіді Codex

1. **Перед редагуванням:** план у 3–6 пунктах і точний список файлів. Чекати «так».
2. **Після редагування:**
   - перелік змінених файлів;
   - виконані команди: вузький `npx vitest run <шлях>`, `npx vue-tsc --noEmit`, `git diff --check`;
   - що перевірено вручну: `?ui=v1` і `?ui=v2` на 375 / 1280px, проходження Tab;
   - що свідомо **не** зроблено і чому.
3. Не стверджувати, що перевірку пройдено, якщо її не запускали.
